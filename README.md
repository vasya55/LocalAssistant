# Local Assistant — офлайн AI-ассистент для Android

Скелет проекта: голосовая команда → локальная LLM (MediaPipe/Gemma) →
структурированная команда → выполнение через Intents и AccessibilityService.
Никакого сетевого доступа: в манифесте нет разрешения `INTERNET`.

## Как собрать

1. Открыть папку в Android Studio (Koala или новее).
2. Скачать квантованную модель Gemma в формате `.task` для MediaPipe LLM Inference:
   https://ai.google.dev/edge/mediapipe/solutions/genai/llm_inference/android
   (модель ~1.5–3 ГБ, кладётся в `assets/models/gemma2b_q4.task` или загружается
   при первом запуске в `filesDir/models/` — сеть нужна только один раз, на этапе
   подготовки APK/первого запуска, дальше приложение офлайн).
3. Скачать модель Vosk для русского языка (`vosk-model-small-ru-0.22`),
   распаковать в `assets/model-ru/`.
4. Собрать `./gradlew assembleDebug`.

## Важные шаги настройки на устройстве

- При первом запуске приложение запросит: микрофон, звонки, SMS, контакты.
- Для управления экраном в произвольных приложениях (клики, ввод текста)
  нужно вручную включить: **Настройки → Специальные возможности → Local Assistant**.
  Android намеренно не позволяет включить это программно — только руками пользователя.

## Архитектура безопасности

- LLM никогда не выполняет код — она только генерирует JSON-команду из
  фиксированного набора (`Command.kt`). Executor валидирует и выполняет.
- Чувствительные действия (звонок, SMS) требуют явного подтверждения
  пользователем в диалоге — это проверяется по типу действия, а не по
  тексту от модели, так что промпт-инъекция через голосовую команду
  не может обойти подтверждение.
- `INTERNET` не запрошен в манифесте — сетевые вызовы физически невозможны
  на уровне ОС, а не просто "не используются в коде".

## Что доделать для продакшна

- Реальный парсинг координат/иерархии окна (сейчас поиск по тексту — простой,
  для сложных UI нужен более умный matcher, возможно, с эмбеддингами описаний).
- Обработка многошаговых сценариев (например, "напиши Ивану в Телеграм" —
  нужна цепочка: open_app → find chat → click → type_text → send).
- UI для истории команд и логов выполнения (полезно для доверия — пользователь
  видит, что именно сделал ассистент).
- Тесты на устройствах разных производителей — некоторые OEM-прошивки
  (MIUI, EMUI и т.п.) сильно ограничивают AccessibilityService в фоне.
- Батарея/производительность: LLM-инференс на устройстве — тяжёлая операция,
  стоит добавить индикатор загрузки и, возможно, кэш недавних команд.
